# Fictional interview test resume

`fictional-ai-ml-resume.txt` and `fictional-ai-ml-resume.pdf` contain the same
invented AI/ML internship profile. Every person, organization, project and metric
is fictional. They contain no real applicant information or API credentials.
Do not replace these fixtures with a real person's resume in Git.

Choose **Use your resume** and upload either file. Earlier browser verification
extracted **4,198 characters** from the PDF, including footer text; exact formatting
may depend on PDF.js. Review the extracted text before proceeding.

- **My real experience** exercises the personal-mode boundary: local reading,
  optional generic role/skill AI questions and local answer feedback under unpaid Gemini.
- **A fictional sample** permits this invented extracted text and made-up answers
  to be sent to Gemini after matching cloud consent.
- Conversation is now the default format. Its provider follow-up/feedback opt-in
  is separate from setup consent. Under unpaid Gemini, use only fictional,
  non-sensitive spoken/typed answers even if the fixture was loaded in personal mode.
- Test role priority by using this ML-heavy fixture with a cashier target.
  Questions should emphasize service/register work rather than ML.

For both conversation and retained individual practice, local speech transcription
does not require an API key. Physical media still needs explicit device consent.
Synthetic audio/video browser fixtures live in `web/tests/fixtures/`; they are
not deployed product routes. See [DEMO](../docs/DEMO.md) for the current procedure
and [HANDOFF](../docs/HANDOFF.md) for source/deployment and evidence boundaries.
